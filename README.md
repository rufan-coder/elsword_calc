# 엘소드 스펙 계산기

엘소드 스탯창 값을 넣으면 **어떤 옵션을 올리는 게 DPS에 가장 이득인지** 계산해 주는 웹 페이지입니다.

**바로 쓰기: https://rufan-coder.github.io/elsword_calc/**

설치나 로그인 없이 브라우저에서 바로 동작하고, 입력한 값과 스크린샷은 브라우저 밖으로 나가지 않습니다.

## 왜 만들었나

스탯창에 보이는 숫자만으로는 어떠한 스탯을 가지고 어느정도 세질 수 있는지 확인하기 어렵습니다.

- 크리티컬·극대화는 쌓을수록 덜 오르는 **점감**이 있습니다.
- 마을 버프, 장비 강화 수치, 파티 버프, 펫의 격려, 전직 패시브처럼 **스탯창에 안 보이는 효과**가 실전에서는 붙습니다.
- 던전마다 **크리티컬 저항**과 **마계 디버프**가 달라 같은 크리티컬 확률·적응력도 가치가 달라집니다.
- 적응력과 재사용 시간 감소는 **상한**이 있어서, 상한을 넘긴 만큼은 아무 효과가 없습니다.

예를 들어 스탯창 크리티컬 83%인 캐릭터는 네블론 레이드에서 실제 평균 95.4%가 되고, 그래서 "크리티컬 6% 추가"의 가치가 스탯창 기준으로 본 것의 절반 아래로 떨어집니다. 이 계산을 매번 손으로 하기 번거로워서 만들었습니다.

## 기능

| 기능 | 하는 일 |
|---|---|
| 실전 수치 | 스탯창 값에 버프·패시브·크리저항을 반영한 평균 크리티컬 확률, 크리티컬 데미지, 극대화, 공격력 %, 최종 적응력, 쿨감, 초목 효율 |
| 옵션 비교 | 옵션을 하나 더했을 때의 DPS 상승률 순위. 가격을 넣으면 가성비 순위 |
| 크극 최적화 | 크리티컬·극대화·보스 데미지 소켓을 어떻게 나누면 DPS가 최대인지 |
| 소켓 최적화 | 소켓 전체(또는 일부)를 7종 마법석으로 다시 채울 때의 최적 조합 |
| 스크린샷으로 채우기 | 게임의 상세 스탯 창 스크린샷에서 수치를 읽어 입력칸을 채움 |
| 악세 세팅 | 캐릭터 창 스크린샷에서 낀 악세·아바타를 아이콘으로 알아보고, 부위별로 바꿔 볼 것을 고르면 세트 효과까지 합친 DPS 변화를 계산 |

화면 위의 메뉴로 **스펙 계산**과 **악세 세팅**을 오갑니다. 악세 세팅은 스펙 계산에 넣은 스탯창 값과 버프를 그대로 씁니다.

지킨 규칙은 하나입니다. **`data`와 `calc`는 화면을 모른다.** 그래서 계산 부분은 브라우저 없이 Node에서 그대로 테스트할 수 있고, 화면을 바꿔도 계산은 건드리지 않습니다.

## 계산 방식

스탯창 값에서 실전 수치를 만드는 순서입니다 (`js/calc/stats.js`의 `resolve`).

1. 스탯창의 크리티컬·극대화 확률에서 점감을 풀어 원래 스탯 합으로 되돌린다.
2. 스텟 합연산 항목(마을 버프, 전직 패시브)을 더한다.
3. 다시 점감을 건다.
4. 곱연산 항목(하의·신발 강화 수치, 황색 아티팩트, 전직 패시브)을 곱한다.
5. 최종 합연산 항목(전직 패시브)을 더하고 던전의 크리티컬 저항을 뺀다.
6. 크리티컬 확률은 펫의 격려를 가동률만큼 반영해 평균을 낸다.
7. 크리티컬 데미지와 보스 데미지에 파티 버프, 길드 스킬, 마을 버프, 전직 패시브를 더한다.
8. 적응력: 최종 적응력 = min(적응력 + 마을 버프, 60%) + 초적응력. 데미지는 1 - max(0, 마계 디버프 - 최종 적응력)배가 된다.
9. 재사용 시간 감소: 강렬·초월 각각 35%까지 적용해 가동률 1/(1 - 쿨감)을 구하고, 딜 점유율로 평균 낸 뒤 DPS 배율 = 1 + 0.24 x (가동률 - 1)로 반영한다. 0.24는 시전 시간 때문에 늘어난 가동률이 딜로 다 이어지지 않는 것을 보정하는 시트의 상수다.

이렇게 만든 수치들의 배율을 곱한 값을 DPS 지수로 쓰고, 옵션을 더하기 전후의 **비율**만 봅니다.

**초목 효율**은 크뎀 곱연산 30%(파티 크뎀 버프와 같은 자리)를 얻고 보뎀 마법석 한 칸을 뺐을 때의 DPS 상승률입니다. "사냥석(2.5%) 뺀 기준/힘트마(3%) 뺀 기준"으로 보여 줍니다.

**악세 교체**(`js/calc/gear.js`)는 스탯창에 이미 지금 장비의 효과가 들어 있다는 점을 이용합니다.

- 바꾼 뒤 스탯창 = 지금 스탯창 - 지금 장비의 효과 + 바꾼 장비의 효과. 크리티컬·극대화는 점감을 풀었다가 다시 겁니다.
- 곱연 크뎀과 최종 데미지는 스탯창에 안 보이므로 양쪽에 따로 곱합니다.
- 세트 효과는 단계별로 쌓입니다(4세트면 2세트 효과도 켜짐). 무기 아바타도 같은 이름의 무악 세트 개수에 들어갑니다.
- 무악 세트는 3개까지만 켜집니다. 바꾼 뒤는 가장 좋은 3개를 자동으로 고르고, 지금 세팅은 게임에서 켜 둔 세트를 고를 수 있게 했습니다.
- 아트마 세트는 다섯 부위 중 4개 이상이면 켜지고, 위 등급부터 세어 4개째가 채워지는 등급이 세트 등급입니다(유니크가 최고).

두 가지 최적화는 어림셈 없이 모든 경우를 따집니다.

- **크극 최적화**: 소켓 수치 0.1% 단위로 약 200만 가지 배분을 전부 계산합니다. 크리티컬 배율과 극대화 배율을 미리 표로 만들어 두어 곱셈만으로 끝납니다.
- **소켓 최적화**: 40칸 안팎을 7종으로 나누는 조합은 수백만 가지가 넘지만, 스탯별 배율이 서로 독립이라 동적 계획법으로 같은 답을 바로 구합니다.

## 스크린샷 인식에서 신경 쓴 점

원칙은 **틀린 값을 넣느니 비워 둔다**입니다. 숫자 하나를 잘못 읽으면 결과가 조용히 틀어지기 때문입니다.

- 수치(하늘색)와 라벨(흰색)을 색으로 갈라 따로 읽습니다. 수치는 숫자만 허용해서 정확도를 높였습니다.
- 숫자는 `83.00%`처럼 형식이 정확히 맞을 때만 받습니다.
- 라벨은 숫자 바로 왼쪽 한 덩어리만 봅니다. 옆 칸 숫자를 놓쳤을 때 그 칸 라벨이 딸려와 값이 엉뚱한 칸에 들어가는 문제가 실제로 있었고, 이렇게 막았습니다.
- 읽은 칸은 화면에 표시해서 사용자가 한 번 확인하게 합니다.

원본 PNG와 75~150% 크기에서는 18개 칸을 모두 맞게 읽었습니다. 글자가 작은 저해상도나 JPEG에서는 일부 칸이 비지만, 시험한 범위에서 틀린 값이 들어간 경우는 없었습니다.

### 장비 아이콘 인식

캐릭터 창의 장비 칸에는 이름이 없고 아이콘만 있어서, 아이콘을 기준표와 비교합니다.

- **기준표**: 게임의 "모험가 장비 리포트"는 부위별로 아이콘과 이름을 같이 보여 줍니다. 이 화면 30장에서 아이콘 143개를 잘라 이름을 시트 데이터와 잇고, 저장소에는 아이콘 그림이 아니라 줄인 특징값(숫자 256개)만 넣었습니다.
- **창 찾기**: 오른쪽 아래 하늘색 "모험가 장비 리포트" 버튼을 기준점으로 잡고, 버튼 위쪽에 창 제목 표시줄이 있는지로 비슷한 버튼과 구분합니다. 버튼 폭으로 화면 배율도 구합니다.
- **배경 지우기**: 아바타 아이콘의 배경색은 캐릭터마다 달라서, 아이콘 가장자리에서 배경색을 알아내 지우고 그림만 비교합니다. 별 표시·옷걸이·자물쇠 자리도 뺍니다.
- **위치 흔들림**: 창 위치가 1~2픽셀만 어긋나도 칸 테두리가 섞여 결과가 흔들려서, 칸을 조금씩 옮겨 보며 가장 잘 맞는 자리를 씁니다.
- **확신**: 1등이 2등보다 충분히 가깝지 않으면 노란 테두리로 표시해 확인하게 합니다. 사용자가 고친 칸은 그 브라우저에 아이콘을 기억해 다음부터 맞춥니다.

실제 캐릭터 창 스크린샷으로 30칸(아바타 악세 11, 일반 악세 12, 한 벌·레어 아바타 6, 무기 아바타 1)을 시험했을 때, 원본·75%·125%·150% 크기·JPEG 모두에서 틀린 칸은 0이었습니다. 다만 아트마 악세는 등급·속성별 아이콘이 거의 같아서 등급과 속성은 직접 고르게 했습니다.

## 검증

```
npm test
```

테스트 67개가 돌아갑니다 (Node 20 이상, 추가 설치 없음).

- **실전 수치와 크극 최적화**: 커뮤니티에서 쓰는 실투력 계산 시트의 예시 캐릭터와 대조합니다. 평균 크리티컬 확률, 크리티컬·극대화 배율, 최적 배분(크리티컬 83.00%, 극대화 65.88%, DPS +0.57%)이 시트와 같습니다.
- **소켓 한 칸의 가치**: 마법석 7종의 한 칸 효율이 시트 값과 소수 6자리까지 같습니다.
- **소켓 최적화**: 모든 조합을 하나씩 세는 느린 방법과 결과가 같은지 비교합니다.
- **적응력·쿨감**: 시트 계산기의 중간값(최종 적응력 70%, 적응력으로 늘어난 데미지 1400%, 쿨감 32%일 때 DPS 배율 1.1129)과 같은지, 상한을 넘긴 만큼은 효과가 없는지 확인합니다.
- **악세 데이터**: 시트에서 옮긴 악세 163개·세트 51종의 개수, 세트 이름 연결, 대표 값이 시트와 같은지 확인합니다.
- **악세 교체**: 같은 장비면 변화가 0인지, 크리 10% 악세를 뺀 결과가 옵션 비교의 크리 -10%와 같은지, 세트 단계·무악 3개 제한·아트마 등급 규칙을 확인합니다.
- **스크린샷 인식**: 비슷한 스탯 이름(적응력과 초적응력 등)을 헷갈리지 않는지, 형식이 어긋난 숫자를 버리는지 확인합니다.
- **아이콘 인식**: 배경색이 달라도 같은 그림을 맞추는지, 위치가 어긋나도 맞추는지, 화면 배율이 달라도 창을 찾는지, 기준표의 모든 줄이 데이터의 아이템을 가리키는지 확인합니다.

```
npm start
```

고친 뒤 `npm test`를 돌려 기존 대조값이 그대로인지 확인합니다. 패치로 값 자체가 달라진 경우에는 `tests/helpers.js`의 기준 캐릭터도 새 값으로 바꿉니다.

## 고쳐서 올릴 때

`index.html`의 `<meta name="build">`와 `js/build.js`의 `BUILD`를 같은 새 값으로 올리고, 맨 아래 "업데이트"에 그 버전의 수정 사항을 적습니다. 테스트가 두 값이 같은지, 업데이트 기록이 있는지 확인합니다.

깃허브 페이지는 파일을 브라우저에 10분쯤 저장해 두게 해서, 배포 직후에는 새 `index.html`과 예전 스크립트가 섞여 열릴 수 있습니다. 실제로 입력칸을 하나 지운 배포 직후에 예전 스크립트가 그 칸을 찾다가 멈춰 화면 전체가 동작하지 않은 적이 있습니다. 그래서 두 버전이 다르거나 시작 중에 오류가 나면, 쓰는 파일을 전부 새로 받아 한 번만 다시 열도록 했습니다.

## 다루지 않는 것

- 동작 속도, 방어력 무시, 재사용 시간 초기화 확률
- 선택 스킬이나 본인 스펙에 따라 달라지는 일부 전직 효과 (해당 전직을 고르면 화면에 안내가 뜹니다)
- 소켓 개수를 스탯창에서 거꾸로 알아내는 것 (장비 고유 옵션과 섞여 있어 구분할 수 없습니다)

## 만든 과정

게임을 하면서 필요해서 시작한 개인 프로젝트입니다. 요구사항 정리, 계산식 확인, 시트와의 대조 검증은 직접 했고, 구현은 AI(Claude)와 함께 했습니다. 계산식은 커뮤니티에 공개된 실투력 계산 문서와 시트를 바탕으로 했습니다.

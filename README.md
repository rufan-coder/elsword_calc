# 엘소드 스펙 계산기

엘소드 스탯창 값을 넣으면 **어떤 옵션을 올리는 게 DPS에 가장 이득인지** 계산해 주는 웹 페이지입니다.

**바로 쓰기: https://rufan-coder.github.io/elsword_calc/**

설치나 로그인 없이 브라우저에서 바로 동작하고, 입력한 값과 스크린샷은 브라우저 밖으로 나가지 않습니다.

## 왜 만들었나

스탯창에 보이는 숫자만으로는 어떠한 스탯을 가지고 어느정도 세질 수 있는지 확인하기 어렵습니다.

- 크리티컬·극대화는 쌓을수록 덜 오르는 **점감**이 있습니다.
- 마을 버프, 장비 강화 수치, 파티 버프, 펫의 격려, 전직 패시브처럼 **스탯창에 안 보이는 효과**가 실전에서는 붙습니다.
- 던전마다 **크리티컬 저항**이 달라 같은 크리티컬 확률도 가치가 달라집니다.

예를 들어 스탯창 크리티컬 83%인 캐릭터는 네블론 레이드에서 실제 평균 95.4%가 되고, 그래서 "크리티컬 6% 추가"의 가치가 스탯창 기준으로 본 것의 절반 아래로 떨어집니다. 이 계산을 매번 손으로 하기 번거로워서 만들었습니다.

## 기능

| 기능 | 하는 일 |
|---|---|
| 실전 수치 | 스탯창 값에 버프·패시브·크리저항을 반영한 평균 크리티컬 확률, 크리티컬 데미지, 극대화, 보스 데미지, 공격력 % |
| 옵션 비교 | 옵션을 하나 더했을 때의 DPS 상승률 순위. 가격을 넣으면 가성비 순위 |
| 크극 최적화 | 크리티컬·극대화·보스 데미지 소켓을 어떻게 나누면 DPS가 최대인지 |
| 소켓 최적화 | 소켓 전체(또는 일부)를 7종 마법석으로 다시 채울 때의 최적 조합 |
| 스크린샷으로 채우기 | 게임의 상세 스탯 창 스크린샷에서 수치를 읽어 입력칸을 채움 |

## 구조

빌드 도구 없이 브라우저가 그대로 읽는 자바스크립트 모듈로 나눴습니다.

```
index.html              화면 뼈대
css/style.css           모양
assets/                 스크린샷 예시 이미지
js/
  main.js               시작점. 입력이 바뀌면 다시 계산해서 각 화면에 넘김
  data/                 게임 수치표 (패치 때 고치는 곳)
    classes.js            전직별 패시브
    dungeons.js           던전별 크리티컬 저항
    buffs.js              마을 버프, 격려, 강화 수치 효과 등
    stones.js             마법석 종류와 한 칸 수치
  calc/                 계산 (화면과 무관한 순수 함수)
    diminish.js           점감
    stats.js              스탯창 값 -> 실전 수치 -> DPS 지수
    buffs.js              버프 세팅 -> 계산용 수치
    compare.js            옵션별 상승률
    optimize-ckb.js       크극 최적화
    optimize-sockets.js   소켓 최적화
  ocr/                  스크린샷 인식
    image.js              스탯 창 위치 찾기, 글자 색만 남기기
    labels.js             스탯 이름 목록
    parse.js              인식된 글자 -> 스탯 값
    recognize.js          글자 인식 엔진 실행 (브라우저 전용)
  ui/                   화면 (읽고, 그리고, 저장)
tests/                  계산·인식 테스트
```

지킨 규칙은 하나입니다. **`data`와 `calc`는 화면을 모른다.** 그래서 계산 부분은 브라우저 없이 Node에서 그대로 테스트할 수 있고, 화면을 바꿔도 계산은 건드리지 않습니다.

## 계산 방식

스탯창 값에서 실전 수치를 만드는 순서입니다 (`js/calc/stats.js`의 `resolve`).

1. 스탯창의 크리티컬·극대화 확률에서 점감을 풀어 원래 스탯 합으로 되돌린다.
2. 스텟 합연산 항목(마을 버프, 전직 패시브)을 더한다.
3. 다시 점감을 건다.
4. 곱연산 항목(하의·신발 강화 수치, 황색 아티팩트, 전직 패시브)을 곱한다.
5. 최종 합연산 항목(전직 패시브)을 더하고 던전의 크리티컬 저항을 뺀다.
6. 크리티컬 확률은 펫의 격려를 가동률만큼 반영해 평균을 낸다.
7. 크리티컬 데미지와 보스 데미지에 파티 버프, 길드 스킬, 전직 패시브를 더한다.

이렇게 만든 수치들의 배율을 곱한 값을 DPS 지수로 쓰고, 옵션을 더하기 전후의 **비율**만 봅니다.

두 가지 최적화는 어림셈 없이 모든 경우를 따집니다.

- **크극 최적화**: 소켓 수치 0.1% 단위로 약 200만 가지 배분을 전부 계산합니다. 크리티컬 배율과 극대화 배율을 미리 표로 만들어 두어 곱셈만으로 끝납니다.
- **소켓 최적화**: 40칸 안팎을 7종으로 나누는 조합은 수백만 가지가 넘지만, 스탯별 배율이 서로 독립이라 동적 계획법으로 같은 답을 바로 구합니다.

## 스크린샷 인식에서 신경 쓴 점

원칙은 **틀린 값을 넣느니 비워 둔다**입니다. 숫자 하나를 잘못 읽으면 결과가 조용히 틀어지기 때문입니다.

- 수치(하늘색)와 라벨(흰색)을 색으로 갈라 따로 읽습니다. 수치는 숫자만 허용해서 정확도를 높였습니다.
- 숫자는 `83.00%`처럼 형식이 정확히 맞을 때만 받습니다.
- 라벨은 숫자 바로 왼쪽 한 덩어리만 봅니다. 옆 칸 숫자를 놓쳤을 때 그 칸 라벨이 딸려와 값이 엉뚱한 칸에 들어가는 문제가 실제로 있었고, 이렇게 막았습니다.
- 읽은 칸은 화면에 표시해서 사용자가 한 번 확인하게 합니다.

원본 PNG와 75~150% 크기에서는 14개 칸을 모두 맞게 읽었습니다. 글자가 작은 저해상도나 JPEG에서는 일부 칸이 비지만, 시험한 범위에서 틀린 값이 들어간 경우는 없었습니다.

## 검증

```
npm test
```

테스트 31개가 돌아갑니다 (Node 20 이상, 추가 설치 없음).

- **실전 수치와 크극 최적화**: 커뮤니티에서 쓰는 실투력 계산 시트의 예시 캐릭터와 대조합니다. 평균 크리티컬 확률, 크리티컬·극대화 배율, 최적 배분(크리티컬 83.00%, 극대화 65.88%, DPS +0.57%)이 시트와 같습니다.
- **소켓 한 칸의 가치**: 마법석 7종의 한 칸 효율이 시트 값과 소수 6자리까지 같습니다.
- **소켓 최적화**: 모든 조합을 하나씩 세는 느린 방법과 결과가 같은지 비교합니다.
- **스크린샷 인식**: 비슷한 스탯 이름을 헷갈리지 않는지, 형식이 어긋난 숫자를 버리는지 확인합니다.

## 내 컴퓨터에서 열기

모듈을 쓰기 때문에 `index.html`을 더블클릭해서는 열리지 않습니다. 간단한 서버로 열어야 합니다.

```
npm start
```

또는 VS Code의 Live Server 확장으로 `index.html`을 열면 됩니다.

## 밸런스 패치 때 고칠 곳

| 바뀐 것 | 고칠 파일 |
|---|---|
| 전직 패시브 수치 | `js/data/classes.js`의 해당 줄 |
| 던전 크리티컬 저항, 새 던전 | `js/data/dungeons.js` |
| 마을 버프, 격려, 강화 수치 효과 | `js/data/buffs.js` |
| 마법석 수치, 소켓 칸 수 | `js/data/stones.js` |
| 상세 스탯 창의 스탯 이름 | `js/ocr/labels.js` |

고친 뒤 `npm test`를 돌려 기존 대조값이 그대로인지 확인합니다. 패치로 값 자체가 달라진 경우에는 `tests/helpers.js`의 기준 캐릭터도 새 값으로 바꿉니다.

## 다루지 않는 것

- 재사용 시간 감소 옵션, 동작 속도, 방어력 무시
- 선택 스킬이나 본인 스펙에 따라 달라지는 일부 전직 효과 (해당 전직을 고르면 화면에 안내가 뜹니다)
- 소켓 개수를 스탯창에서 거꾸로 알아내는 것 (장비 고유 옵션과 섞여 있어 구분할 수 없습니다)

## 만든 과정

게임을 하면서 필요해서 시작한 개인 프로젝트입니다. 요구사항 정리, 계산식 확인, 시트와의 대조 검증은 직접 했고, 구현은 AI(Claude)와 함께 했습니다. 계산식은 커뮤니티에 공개된 실투력 계산 문서와 시트를 바탕으로 했습니다.
